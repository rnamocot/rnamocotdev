Make.com Tutorial: How to Build Automation Scenarios That Actually Work

Learn Make (formerly Integromat): scenarios, modules, routers, filters, iterators, error handlers and a step-by-step WooCommerce order workflow.

Short answer: Make (formerly Integromat) is a visual automation platform where you drag modules onto a canvas to build “scenarios” that move data between apps. It shines for complex, multi-branch workflows that non-developers still need to understand. Plan your data flow first, use routers and filters for logic, and add error handlers before you go live.

What is Make and when should you use it?

Make is a cloud-based, no-code automation tool with thousands of app integrations. Its visual canvas shows exactly how data flows from one step to the next, which makes it easier to follow than a linear list of steps. Make is a strong choice when:

  • Your workflow has several branches or conditions (for example, different actions per product or lead type).
  • You need to process lists: every line item in an order, every row in a sheet, every attachment in an email.
  • Your team wants a visual tool they can maintain without writing code.
  • You don’t want to host or maintain servers.

If you need self-hosting or very high volume, compare it with n8n. For simple two-step automations, Zapier is often quickest to set up.

Key Make concepts

  • Scenario: a complete automation, the equivalent of a “Zap” or n8n workflow.
  • Modules: individual steps. Triggers start the scenario, actions create or update data, searches look data up.
  • Instant vs polling triggers: instant triggers (webhooks) run the moment something happens; polling triggers check for new data on a schedule, such as every 15 minutes.
  • Bundles: each record that flows through a scenario. One new order is one bundle.
  • Mapping: click fields from earlier modules to insert them into later ones, and use built-in functions to format dates, text and numbers.
  • Credits: Make bills by usage. Most module runs consume credits (previously called operations), so efficient design directly lowers your bill.

Routers, filters, iterators and aggregators

These four tools are what make Make powerful:

ToolWhat it doesExample
RouterSplits one flow into several branchesSend B2B and retail orders down different paths
FilterLets a bundle continue only if conditions matchOnly orders over $200 trigger a VIP email
IteratorTurns an array into separate bundlesProcess each line item in an order individually
AggregatorCombines bundles back into oneBuild one summary email from many rows

Add a fallback route to your routers so bundles that match no condition are still handled instead of silently dropped.

Step by step: a WooCommerce order workflow

This scenario records every new order, alerts the team about large orders and sends customers a personalised follow-up.

  1. Create a scenario and add the WooCommerce: Watch Orders trigger, or a Custom Webhook connected to a WooCommerce webhook for instant runs. Connect your store with REST API keys from WooCommerce → Settings → Advanced.
  2. Run once and place a test order, so Make learns the data structure and you can map fields.
  3. Add a Google Sheets “Add a Row” module and map order number, date, customer, total and status.
  4. Add a router with two routes. Route one gets a filter: Total greater than 200. Route two is the fallback.
  5. Route one: post a Slack message to your sales channel with the order details and a link to the order.
  6. Both routes: add an AI module (OpenAI, Anthropic Claude or Make AI) to draft a short thank-you message based on the products ordered, then send it with Gmail, Brevo or Mailchimp after a delay.
  7. Schedule it. Instant webhooks run immediately; for polling triggers, choose a sensible interval. Then switch the scenario on.

Error handling in Make

Right-click any module and choose Add error handler. Make gives you five directives:

  • Resume: substitute a fallback value and continue.
  • Ignore: skip the failed bundle and carry on.
  • Break: stop, store the run as an incomplete execution and retry it later automatically.
  • Commit: stop, but keep the changes already made.
  • Rollback: stop and undo changes where the apps support it.

For API calls that can time out, Break with automatic retries is usually the right choice. Also enable email notifications for failed scenarios so problems don’t go unnoticed.

How to keep Make costs down

  • Filter early. Put filters right after the trigger so irrelevant bundles stop before they use credits.
  • Prefer webhooks over frequent polling. A polling trigger that runs every minute uses credits even when nothing changed.
  • Aggregate before sending. One summary email instead of fifty individual messages.
  • Use data stores to remember what you’ve already processed and avoid duplicates.
  • Review scenario history monthly to find the scenarios using the most credits.
